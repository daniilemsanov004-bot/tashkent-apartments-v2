# Квартиры Ташкент — поиск объявлений от собственников

Находит новые объявления (аренда + продажа) на **OLX.uz** и **Uybor.uz**,
показывает их на сайте и шлёт в Telegram. Только сегодняшние объявления.

## Архитектура (бесплатная связка для теста)

```
GitHub Actions (по расписанию, каждые ~15 мин)
    └─ scraper/  — парсит сайты, пишет в Supabase, шлёт в Telegram

Supabase — база данных (Postgres), общая для скрапера и сайта

Vercel — хостинг сайта
    └─ client/         — React-интерфейс (лента, фильтры, поиск)
    └─ client/api/     — serverless-функции (отдают данные из Supabase на фронт)
```

Ничего не должно быть постоянно включено на вашем компьютере — все
три сервиса работают в облаке. Всё на бесплатных тарифах.

## Настройка — по порядку

### 1. Supabase (база данных)

1. Зарегистрироваться на **supabase.com**, создать новый проект.
2. **SQL Editor** → New query → вставить содержимое файла
   `supabase/schema.sql` из этого проекта → **Run**. Это создаст таблицу
   `listings`.
3. **Project Settings → API** — скопировать:
   - `Project URL` → это `SUPABASE_URL`
   - `service_role` ключ (НЕ `anon`!) → это `SUPABASE_SERVICE_KEY`

⚠️ `service_role` даёт полный доступ к базе без ограничений — держите
его только в GitHub Secrets и Vercel Environment Variables, никогда
не коммитьте в код и не используйте во фронтенд-коде напрямую.

### 2. Telegram

1. **@BotFather** → `/newbot` → получить `TELEGRAM_BOT_TOKEN`.
2. **@userinfobot** → `/start` → получить свой `TELEGRAM_CHAT_ID`.
3. Написать `/start` своему новому боту (иначе он не сможет писать вам первым).

### 3. Локальный тест скрапера (по желанию, перед тем как заливать на GitHub)

```bash
cd scraper
npm install
cp .env.example .env
# вписать в .env: SUPABASE_URL, SUPABASE_SERVICE_KEY, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
npm start
```
Если всё настроено верно — в консоли будет видно найденные объявления,
а в Supabase (Table Editor → listings) появятся строки.

### 4. GitHub — чтобы скрапер работал сам по расписанию

1. Залить этот проект в свой репозиторий на GitHub (если ещё не там).
2. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.
   Добавить все 6 секретов:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_KEY`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `USE_AI_CLASSIFICATION` — значение `false` пока
   - `ANTHROPIC_API_KEY` — можно оставить пустым, если ИИ выключен
3. Workflow уже лежит в `.github/workflows/scrape.yml` — как только секреты
   добавлены, он начнёт запускаться сам каждые ~15 минут.
4. Проверить вручную: вкладка **Actions** в репозитории → workflow
   "Scrape apartments" → **Run workflow** — запустит сразу, не дожидаясь расписания.

### 5. Vercel — сайт

1. Зарегистрироваться на **vercel.com**, **Add New → Project**,
   подключить тот же GitHub-репозиторий.
2. **Root Directory** — указать `client` (важно! иначе Vercel не найдёт проект).
3. **Environment Variables** — добавить:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_KEY`
4. **Deploy**. Через минуту Vercel даст ссылку вида
   `https://tashkent-apartments-xxxx.vercel.app` — это и есть готовый сайт.

Дальше при каждом изменении кода в GitHub Vercel будет пересобирать сайт
автоматически.

## Локальная разработка интерфейса

```bash
cd client
npm install
npm run dev
```
Откроет **http://localhost:5173** — но `/api/*` не заработает без
`vercel dev` (см. ниже), так что ленту вы не увидите — зато удобно
для правки вёрстки/стилей.

Чтобы протестировать с реально работающим API локально:
```bash
npm install -g vercel
cd client
vercel dev
```
Спросит логин через Vercel — дальше эмулирует и фронтенд, и `/api`
на одном порту, как в проде.

## Логика "собственник / агент"

По умолчанию ИИ-классификация выключена — присылаются все новые
объявления без разбора. Чтобы включить: `USE_AI_CLASSIFICATION=true`
в GitHub Secrets + `ANTHROPIC_API_KEY`. Порог настроен так, чтобы не
упустить ни одного реального собственника — не показываются только
объявления, где модель уверенно распознала агента.

## Статус "связались"

Кнопка на карточке — хранится в Supabase, общая для всех, кто заходит
на сайт (если пользуются несколько агентов — оба видят одну картину).

## Про Uybor

Подключён через их внутренний JSON API (`api.uybor.uz`), а не через
парсинг HTML — сайт рендерит объявления через JavaScript, обычный
запрос видел бы пустую страницу. Структура ответа API была определена
по частичным данным (см. комментарии в `scraper/src/scrapers/uybor.js`)
— если после первого реального запуска какие-то поля (цена, телефон)
окажутся пустыми в интерфейсе, в логах GitHub Actions будет напечатан
пример сырого JSON-объявления — пришлите его, поправим маппинг полей.

## Если селекторы OLX сломались

Если в логах Actions видно "0 объявлений" для OLX — вёрстка могла
измениться. Открыть раздел в браузере → DevTools → Elements → поправить
`scraper/src/scrapers/olx.js`.

## Если понадобится больше мощности/точности — переезд на VPS

Бесплатная связка ограничена: GitHub Actions может задерживать запуск
на несколько минут, лимиты по минутам в месяц. Когда почувствуете, что
инструмент реально нужен постоянно — можно перенести `scraper/` на VPS
с постоянным циклом (`node-cron`) вместо GitHub Actions — это уже
обсуждалось отдельно, спросите, если понадобится.
