# Квартиры Ташкент — поиск объявлений от собственников

## ⚠️ Статус на 06.08.2026 — что сделано и что доделать

**Уже готово и работает:**
1. Сайт (React + Supabase) — лента объявлений, фильтры, авторизация по
   email, статус "связались", команда/роли.
2. Скрапер (OLX.uz, Uybor.uz, Realting.uz) — квартиры + дома +
   коммерция, аренда и продажа, работает по расписанию через GitHub
   Actions.
3. **Интерактивный бот в Telegram полностью реализован**
   (`client/api/telegram-webhook.js`) — команда `/start` или `/find`
   запускает мастер из кнопок: тип сделки → тип недвижимости → район
   (можно несколько) → комнаты → цена → результаты с пагинацией
   "Ещё". Настройка — см. подробный комментарий в самом начале файла
   `telegram-webhook.js` (нужно один раз добавить
   `TELEGRAM_WEBHOOK_SECRET` в Vercel и зарегистрировать webhook).
4. **ИИ-классификация полностью отключена** (06.08.2026, по решению).
   Собственник/агент теперь определяется ТОЛЬКО жёсткими бесплатными
   правилами: сколько у продавца объявлений недвижимости, метка
   "организация"/"риелтор" от самого сайта, метка Realting.uz
   "от собственника". Код ИИ-классификации (`scraper/src/classify.js`)
   не удалён — просто не вызывается (см. `USE_AI_CLASSIFICATION` в
   `scraper/src/run.js`), на случай если понадобится вернуть в
   будущем. Нигде в интерфейсе/уведомлениях больше не упоминается
   "ИИ" — объявления, которые прошли только эвристики (не подтверждены
   явной меткой сайта), теперь подписываются просто "Собственник" /
   "Скорее всего собственник".

**Осталось доделать:**
1. **Телефон с OLX.uz достаётся не всегда.** Номер на OLX часто
   спрятан за кнопкой "показать номер" и подгружается отдельным
   запросом — сейчас телефон берётся, только если продавец написал

   логах GitHub Actions видно, что номер по-прежнему не находится —
   пришлите лог, там будет напечатана структура ответа, поправим.
2. **Uybor.uz — категории "Дома" и "Коммерция"** не подключены — нужно

   → вкладка Network → найти запрос к `api.uybor.uz/api/v1/listings` →

   в `scraper/src/scrapers/uybor.js`.
3. **Realting.uz — URL для домов/коммерции не проверены вживую**
   (только для квартир подтверждено реальным запуском) — если после

   открыть сайт и свериться со `scraper/src/scrapers/realting.js`.



Находит новые объявления (аренда + продажа) на **OLX.uz**, **Uybor.uz**
и **Realting.uz**, показывает их на сайте и шлёт в Telegram. Только
сегодняшние объявления.

## Архитектура (бесплатная связка для теста)

```
GitHub Actions (по расписанию, каждые ~15 мин)
    └─ scraper/  — парсит сайты, пишет в Supabase, шлёт в Telegram

Supabase — база данных (Postgres), общая для скрапера и сайта

Vercel — хостинг сайта
    └─ client/         — React-интерфейс (лента, фильтры, поиск)
    └─ client/api/     — serverless-функции (отдают данные из Supabase на фронт)
```

Ничего не должно быть постоянно включено на вашем компьютере — все
три сервиса работают в облаке. Всё на бесплатных тарифах.

## Настройка — по порядку

### 1. Supabase (база данных)

1. Зарегистрироваться на **supabase.com**, создать новый проект.
2. **SQL Editor** → New query → вставить содержимое файла
   `supabase/schema.sql` из этого проекта → **Run**. Это создаст таблицу
   `listings`.
3. **Project Settings → API** — скопировать:
   - `Project URL` → это `SUPABASE_URL`
   - `service_role` ключ (НЕ `anon`!) → это `SUPABASE_SERVICE_KEY`

⚠️ `service_role` даёт полный доступ к базе без ограничений — держите
его только в GitHub Secrets и Vercel Environment Variables, никогда
не коммитьте в код и не используйте во фронтенд-коде напрямую.

### 2. Telegram

1. **@BotFather** → `/newbot` → получить `TELEGRAM_BOT_TOKEN`.
2. **@userinfobot** → `/start` → получить свой `TELEGRAM_CHAT_ID`.
3. Написать `/start` своему новому боту (иначе он не сможет писать вам первым).

### 3. Локальный тест скрапера (по желанию, перед тем как заливать на GitHub)

```bash
cd scraper
npm install
cp .env.example .env
# вписать в .env: SUPABASE_URL, SUPABASE_SERVICE_KEY, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
npm start
```
Если всё настроено верно — в консоли будет видно найденные объявления,
а в Supabase (Table Editor → listings) появятся строки.

### 4. GitHub — чтобы скрапер работал сам по расписанию

1. Залить этот проект в свой репозиторий на GitHub (если ещё не там).
2. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.
   Добавить 4 секрета:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_KEY`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`

   `USE_AI_CLASSIFICATION` и `ANTHROPIC_API_KEY` добавлять больше не
   нужно — ИИ-классификация отключена прямо в коде (см. раздел про
   собственник/агент ниже), эти секреты ни на что не влияют, даже
   если остались в GitHub с прошлого раза.
3. Workflow уже лежит в `.github/workflows/scrape.yml` — как только секреты
   добавлены, он начнёт запускаться сам каждые ~15 минут.
4. Проверить вручную: вкладка **Actions** в репозитории → workflow
   "Scrape apartments" → **Run workflow** — запустит сразу, не дожидаясь расписания.

### 5. Vercel — сайт

1. Зарегистрироваться на **vercel.com**, **Add New → Project**,
   подключить тот же GitHub-репозиторий.
2. **Root Directory** — указать `client` (важно! иначе Vercel не найдёт проект).
3. **Environment Variables** — добавить:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_KEY`
4. **Deploy**. Через минуту Vercel даст ссылку вида
   `https://tashkent-apartments-xxxx.vercel.app` — это и есть готовый сайт.

Дальше при каждом изменении кода в GitHub Vercel будет пересобирать сайт
автоматически.

## Локальная разработка интерфейса

```bash
cd client
npm install
npm run dev
```
Откроет **http://localhost:5173** — но `/api/*` не заработает без
`vercel dev` (см. ниже), так что ленту вы не увидите — зато удобно
для правки вёрстки/стилей.

Чтобы протестировать с реально работающим API локально:
```bash
npm install -g vercel
cd client
vercel dev
```
Спросит логин через Vercel — дальше эмулирует и фронтенд, и `/api`
на одном порту, как в проде.

## Логика "собственник / агент"

Определяется только жёсткими бесплатными правилами, без ИИ:
- если у продавца больше 2 объявлений недвижимости — считаем агентом
  (`SELLER_LISTINGS_AGENT_THRESHOLD` в `scraper/src/classify.js`);
- если сам сайт пометил аккаунт как организацию/риелтора — агент;
- если Realting.uz показал объявление на своей странице "от
  собственников" — собственник, без дополнительных проверок.

Всё, что не попало ни под одно из этих правил, помечается как
"Скорее всего собственник" (не скрывается, но помечено как
неподтверждённое) — таких большинство, порог специально настроен так,
чтобы не упустить ни одного реального собственника. Агентства
(подтверждённые правилами выше) не показываются ни на сайте, ни в
Telegram.

## Авторизация — кто может видеть сайт

Сайт больше не открыт всем подряд — нужно войти по email (без пароля,
через ссылку на почту). Заходить может только тот, чей email есть в
таблице `team_members` в Supabase; любой уже впущенный человек может
пригласить нового прямо на сайте (кнопка "👥 Команда").

### Настройка (один раз)

1. **Supabase → Authentication → Providers** — убедитесь, что **Email**
   включён (обычно включён по умолчанию).
2. **Supabase → Authentication → URL Configuration**:
   - **Site URL** — впишите адрес вашего сайта на Vercel (например,
     `https://tashkent-apartments-v2.vercel.app`)
   - **Redirect URLs** — добавьте туда же этот адрес (можно с `/**` на
     конце, чтобы разрешить все пути)
3. **Supabase → SQL Editor** — выполните `supabase/02_team_access.sql`,
   заменив в нём email на свой собственный (первый человек с доступом).
4. **Supabase → Project Settings → API Keys** — возьмите **anon public**
   ключ (не service_role! это другой, публичный ключ, специально для браузера).
5. **Vercel → Project Settings → Environment Variables** — добавьте:
   - `VITE_SUPABASE_URL` — тот же URL, что и `SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY` — anon-ключ из шага 4
6. Передеплоить сайт (пуш в GitHub или Redeploy в Vercel).

После этого при заходе на сайт будет экран входа: вводите email →
приходит письмо со ссылкой → переходите по ней → попадаете на сайт
уже авторизованным. Пригласить нового человека — кнопка "👥 Команда"
в шапке сайта, вписать его email.

## Статус "связались"

Кнопка на карточке — хранится в Supabase, общая для всех, кто заходит
на сайт (если пользуются несколько агентов — оба видят одну картину).

## Про Uybor

Подключён через их внутренний JSON API (`api.uybor.uz`), а не через
парсинг HTML — сайт рендерит объявления через JavaScript, обычный
запрос видел бы пустую страницу. Структура ответа API была определена
по частичным данным (см. комментарии в `scraper/src/scrapers/uybor.js`)
— если после первого реального запуска какие-то поля (цена, телефон)
окажутся пустыми в интерфейсе, в логах GitHub Actions будет напечатан
пример сырого JSON-объявления — пришлите его, поправим маппинг полей.

## Если селекторы OLX сломались

Если в логах Actions видно "0 объявлений" для OLX — вёрстка могла
измениться. Открыть раздел в браузере → DevTools → Elements → поправить
`scraper/src/scrapers/olx.js`.

## Если понадобится больше мощности/точности — переезд на VPS

Бесплатная связка ограничена: GitHub Actions может задерживать запуск
на несколько минут, лимиты по минутам в месяц. Когда почувствуете, что
инструмент реально нужен постоянно — можно перенести `scraper/` на VPS
с постоянным циклом (`node-cron`) вместо GitHub Actions — это уже
обсуждалось отдельно, спросите, если понадобится.
